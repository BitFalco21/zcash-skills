**Observed source evidence**

- Production dispatch is `commands::run` → `Runtime::start` → `own_start` → `start_owned`. `own_start` claims the start lock, takes the lifecycle lock, and publishes a session **before Docker preflight**. `StartOwnership` retains ownership through cleanup ([startup.rs](/private/tmp/zcash-skills-eval-followup-20261016/foreign-resource/without-skill/crates/ths-cli/src/runtime/startup.rs:4)).
- `owned_resource` matches exact names, then `inspected_resource_identity` requires `com.zakura.ths.instance=alpha`. Missing and different labels both produce “refusing to reuse or delete it.” Containers/networks use IDs; volumes use names ([resources.rs](/private/tmp/zcash-skills-eval-followup-20261016/foreign-resource/without-skill/crates/ths-cli/src/runtime/resources.rs:21)).
- `DockerHost::delete` invokes `cleanup_core(partial=false)`. It inspects the fixed expected resource set before entering the removal loop. An unowned volume aborts that preflight, so even previously inspected owned resources are preserved. This is not a prefix sweep ([cleanup.rs](/private/tmp/zcash-skills-eval-followup-20261016/foreign-resource/without-skill/crates/ths-cli/src/runtime/cleanup.rs:123)).
- `start_owned` initializes `CleanupOnDrop` as `Inactive`, verifies initial cleanup, then arms it. Initial `Err` **or an unverified report** returns without allocation or a Drop retry. After allocation/readiness/shutdown, it sets `Explicit` before calling `delete_partial`, preventing a second attempt if explicit cleanup fails ([startup.rs](/private/tmp/zcash-skills-eval-followup-20261016/foreign-resource/without-skill/crates/ths-cli/src/runtime/startup.rs:620)).
- Partial cleanup may remove independently verified owned resources while reporting foreign collisions. Recovery records preserve mutation identities and dependencies; unresolved allocation dependencies remain protected. Metadata is removed only after verified cleanup and helper completion. Recorded container/network IDs prevent adopting a replacement; failed inspection alone is not proof of absence. Volumes lack an independent generation ID, so their name plus ownership check cannot distinguish every same-label replacement.
- `stop`/`reset` use `verified_cleanup_with`: request the active session to stop, wait for ownership, reject superseding owners, then verify leftovers. `DeletedElsewhere` makes foreground startup exit without deleting again ([instance.rs](/private/tmp/zcash-skills-eval-followup-20261016/foreign-resource/without-skill/crates/ths-cli/src/runtime/instance.rs:372)).

The safe response is to preserve the unowned volume and fail visibly. An explicitly selected different instance name avoids the collision; deleting foreign data requires a separate, informed user action.
