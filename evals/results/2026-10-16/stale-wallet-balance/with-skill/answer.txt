Proposed diagnostic procedure, **not executed**:

1. **Establish instance and artifact identity first.** Record the intended instance, dashboard origin, container identity, immutable image ID/digest, build inputs, and served frontend asset hashes. Compare these with the edited checkout; a matching version tag alone is insufficient. If the image lacks the edits, rebuild and recreate the app before assessing the change. The documented build path is `cargo run -p thus-spoke-zakura -- build --dev`; rebuilding alone does not replace an existing container.

2. **Compare raw server responses around the symptom.** Capture `/api/v1/health`, `/api/v1/status`, `/api/v1/accounts`, and `/api/v1/mining/jobs` from that same instance, with timestamps. Inspect:
   - Node height **and hash**, wallet observed/scanned heights **and hashes**, `state`, `error`, and `last_success_at`.
   - `settled` and `settlement_blocker`; `api/status.rs::settlement_status` distinguishes unavailable components, height/hash mismatch, and wallet lag.
   - Mining job state, count, error, and `progress_uncertain`. `mining.rs::MiningCoordinator::run` can report all blocks generated yet fail synchronization.

   Use raw JSON: `web/src/lib/api/schemas.ts` currently omits wallet hashes and settlement fields from its parsed status contract.

3. **If accounts are stale, trace server publication.** Follow `rpc.rs` → `reconcile.rs::sync_wallet` (lightwalletd, rewind, transparent discovery, shielded scans) → `wallet.rs::apply_balances` → `sync.rs::refresh_wallet_snapshot_until`. Correlate app/lightwalletd logs with the reported failure phase and checkpoint. Equal heights alone cannot exclude a reorg. The background loop attempts reconciliation about every two seconds; that is not a guaranteed completion delay.

4. **If accounts are current but the display differs, trace the browser query.** Follow `api/endpoints.ts::api.accounts` → `client.ts::request` and `accountSchema` → `hooks/queries.ts::useAccounts`, key `['accounts']` → `WalletPage`. Compare the response, schema errors, query data/update time, and rendered amount. In `hooks/useServerEvents.ts`, only `wallet` directly invalidates accounts; `chain`, `sync`, and `mining` target other queries. Mining admission in `useStartMining` refreshes mining state only. Check actual SSE delivery and the resulting accounts request. Server-side SSE lag emits `resync`, but `api/events.rs` supplies no event IDs/replay; reconnecting alone does not prove cache freshness.
